## 逐条处置

### D01 校验错误仍未统一 · 成立 · 已修

复核列的五种输入我都复现了，全是原生错误漏出：

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `battery = 66.5` | `22P02` | `invalid_payload` |
| `unlock_count = 1.5` | `22P02` | `invalid_payload` |
| `unlock_count = 2147483648` | `22003` | `invalid_payload` |
| `accuracy = 1e40` | `22003` | `invalid_payload` |
| 同批两条 `package_name` 相同 | `21000` | `invalid_payload` |

做法：整数列先按 `numeric` 取值，验整数性（`v = trunc(v)`）与目标类型容量，再转型；包名重复显式拒绝，而不是让它撞上 `ON CONFLICT DO UPDATE` 的「不能二次影响同一行」。

同时接受复核的一个边界观点：**参数绑定阶段的错误转换不了**。比如 `p_date` 传个非日期，请求根本进不到函数体，只能是 `22007`。契约里已经把这两类分开写，不再承诺「所有错误都是 invalid_payload」。

### D02 RPC 示例三处错 · 成立 · 已改文档

1. 「响应永远是数组」范围过大 → 改成按返回类型分列：两个读入口是数组，`report_locations` 是对象，`report_usage` 是裸数字，配对码与 couple id 是字符串，设置类是 void。
2. void RPC 写死 `200` + `Content-Length: 0` → 改成「2xx + 空体」，并注明 PostgREST 13 通常回 204、线上实测后再回填。客户端规则是「按类型解码，不校验具体状态码与头」。
3. 「指向不存在的人返回 `[]`」→ 改成 `not_allowed`。函数是先判权限再查数据，传一个既非本人也非对象的 UUID，即使不存在也先拒；只有「自己没配对又不指定目标」才返回空集。

**仍欠一次实测**：真实 JWT 下四种返回形状的实际状态码与响应体。这条记在未验清单里。

### D03 用机上报不发刷新信号 · 成立 · 已修

复现方式与复核一致：记下 `presence.updated_at`，只调 `report_usage`，返回值 1，时间戳一模一样。

修法：写入成功后在同一事务里 `insert ... on conflict do update set updated_at = now()`。刻意**不碰 `last_report_at`**——那一列只表示位置采集时刻；也**不在返回 -1 时推进**，旧快照不算新数据。

验收加了 V25。

### D04 对称索引作用被夸大 · 成立 · 只改文案

复核说得对：`couples_pair_active` 只挡同一对人正反两向重复，挡不住「已有 A–B，再插 C–A」。我在 004 的注释里写了「对称索引才真正约束住一人一段」，这句过强。

处置：

- 契约 v0.3 写明一人一段由三件事共同保证：`couple_members.user_id` 主键、受控配对函数、锁内重查
- **不修改 004 文件**，保证与线上执行的那一份字节一致；更正写在 005 头部注释与本文件里
- 验证补交叉用例：普通 JWT 走配对函数，A–B 存在时 C–A 返回 `partner_already_paired`

**接受的风险**：管理员直连数据库可以造出交叉配对。这不在客户端可达面里，v0.1 不额外加触发器去堵。如果以后要堵，加一个 `couples` 上的 BEFORE INSERT 触发器即可，属于运维面加固。

### D05 时间格式说明没改干净 · 成立 · 已改

第 539 行映射表还写着「ISO-8601 带 Z」，改成「带 `Z` 或有效偏移」。

关于 `Instant.parse`：复核认为我说「它只吃 Z」过于绝对。我在本机 JDK 17.0.2 上实测：

```
Instant.parse("2026-10-26T00:00:00+08:00") = 2026-10-25T16:00:00Z   ← 接受偏移
Instant.parse("2026-10-26T00:00:00")       → DateTimeParseException
```

所以复核对，我错。契约改为：桌面 JDK 17 实测接受偏移，但安卓运行库未在目标机型验证，仍统一用 `OffsetDateTime.parse(...).toInstant()`，理由写成「对偏移的支持写在规格里，不依赖运行库版本」，并删掉无版本限定的断言。

### D06 权限摘要与验证状态冲突 · 成立 · 已改文档

- 「写全部走函数」→ 改成「大部分走函数，两处例外：`profiles` 两列、`devices` 本人整行，都是数据库真允许的」
- `profiles` 的「否」改成「是（仅两列）」
