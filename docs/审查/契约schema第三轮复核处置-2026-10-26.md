## E01 校验通过后仍按原始文本转换整数 · 成立 · 已修

我复现的现象与复核一致：

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| 位置点 `battery: 66.0` | `22P02` smallint | 接受，存 66 |
| 应用 `foreground_ms: 1000.0` | `22P02` bigint | 接受，存 1000 |
| 应用 `launch_count: 3.0` | `22P02` int | 接受，存 3 |
| 日汇总 `screen_on_ms: 1000.0` | 本来就正常 | 正常 |

根因说清了：005 先转 `numeric` 判整数性（`v = trunc(v)`），但入库时又从原始文本 `->>` 取字符串直接转 `smallint` / `bigint` / `int`。`66.0` 的数值是整数、写法带小数点，能通过整数性判断，却在第二次转型时炸。

改法（`docs/006-contract-fix3.sql`）：四处转换统一改成 `::numeric::目标类型`。整数性与范围检查全部保留在前面，所以真小数（66.5）仍然被拒，不会被静默舍入成 66。

**没有就地改 005**——它和线上执行的那份字节一致才有校验价值，所以按追加迁移处理。
