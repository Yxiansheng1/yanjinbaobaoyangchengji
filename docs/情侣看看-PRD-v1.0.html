01产品定位

一个只给两个人在用的 App。她打开能看见你在哪，你打开能看见她今天怎么用手机的。没有订阅，没有广告，数据存在自己的库里。

它的重心不是数据，是一句话说清对方现在怎么样。「她 21:40 到家，刷了四十分钟抖音，23:10 锁屏」比十条折线图有用。

能力不对称

她用的是安卓，你用的是 iPhone。iOS 不给第三方读应用使用和屏幕时间，所以你能看见她的全部，她只能看见你的位置和电量。这个不对称是系统限制，改不了，写在需求里作为前提。

02市场空档

现有产品分两类，各自都缺一块。

类别代表做了什么缺什么
定位类Bump、whoo、Life360、时刻守护实时位置、停留时长、电量、幽灵模式、到离提醒不碰用机数据
情侣类小恩爱、恋爱记定位、纪念日、相册、养成、商城用机记录做得浅，商业化过重
自律类Jolt、Habi、LockPact互相监督专注不做位置

价格是这个市场里最明显的痛点。小恩爱 25 元一个月、198 元一年；时刻守护的双人年费约 45 欧元；恋爱记的补签卡单卖 25 到 208 元，公开报道里有用户为了一次打卡续到 2026 年的会员。

要做的事很简单：把定位和用机这两件事做透，其余一律不加价。

03用户与场景

主用户

两个人。一个安卓一个 iPhone。有稳定的关系，愿意互相看见，但都不想被当成被监控的对象。

三个场景决定产品形态

场景用户想知道产品要给
早上她到公司了吗一条位置变化，加一个地点名
晚上她今天在手机上干嘛了屏幕时间、Top 应用、解锁次数
半夜她睡了没最近一次解锁时间

不做的用户

不做多人、不做家人、不做孩子、不做陌生人。一个账号只能绑定一个人，绑了就锁死，解绑要双方都看到。

04设计原则

  1. 看得见，但能退出。暂停共享必须一步可达，暂停时对方看到的是「已暂停」，不是假装还在。
  2. 给结论，不给原始数据。默认展示一句话总结，明细折叠在下一层。
  3. 后台不吵。常驻服务只在状态异常时打扰人，平时安静。
  4. 省电优先于精度。位置按移动状态变速采集，静止时降频。
  5. 数据可带走。用标准 Postgres，随时能整库导出搬走。

06v0.1 详细需求

第一版 13 项，目标 2 到 3 周。判断标准是能不能每天用，不是好看。

H1 注册登录

流程
邮箱、密码、昵称三项。注册后自动登录，token 存本地，30 天免登录。
边界
不做邮箱验证、不做找回密码、不做第三方登录。密码至少 8 位。登录失败 5 次锁 10 分钟。

H2 配对绑定

流程
A 点「生成配对码」得到六位数字，10 分钟有效。B 输入后写入 couples 表，双方进入已绑定状态。
边界
一人只能绑一个。已绑定时不能再生成码。解绑不在一版范围内。

H4 服务器

范围
Supabase 免费档，区域选新加坡。用 Auth 管账号，Postgres 存数据，Realtime 推位置变化，Row Level Security 保证只能读到自己和对象的数据。

H5 安卓后台常驻

做什么
前台服务常驻，通知栏一条不可关闭的低优先级通知。位置按移动状态采集：静止 5 分钟一次，移动 30 秒一次。
保活
首次启动引导用户完成四项设置：电池优化白名单、自启动、后台无限制、锁屏保持运行。按品牌给不同的跳转路径，小米、华为、OPPO、vivo 各一套。
验收
锁屏 30 分钟后位置仍在更新。24 小时耗电增量不超过 8%。

A1 实时位置

展示
主页地图上一枚头像。上方一行字写「现在在公司，2 分钟前更新」。点开看详情。
刷新
对方 App 在前台时常驻长连接，秒级。后台时靠推送，30 秒到 5 分钟一次，取决于移动状态。
降级
超过 10 分钟没更新，头像变灰，文案改成「最后位置，10 分钟前」。超过 2 小时显示「长时间未更新」。

A2 地点语义

做什么
把坐标变成中文地名，走逆地理编码。v0.1 只做到这一层。
边界
常去点的聚类、自动识别家或公司、手动命名，都排到 v0.2。v0.1 不做七天候选点，也不做地点管理入口。

A9 电量与充电

展示
头像旁一个小电池，低于 20% 变红，充电时显示闪电。随位置一起上报，不单独轮询。

A10 幽灵模式·精确

说明
默认状态，就是正常共享。一版不做模糊和冻结，但设置项的位置先留出来。

G1 一键暂停共享

交互
主页右上角一个按钮，点开选时长：1 小时、今晚、手动恢复。暂停期间头像位置不再更新。
对方看到什么
明确的「她已暂停共享，22:00 恢复」。不能显示成离线或最后位置，那等于骗人。
数据
暂停期间位置、电量、用机三类全部停止共享，也不采集不上报。要单独关某一项，用 G2 的分项开关；暂停优先于分项开关。

G2 分项开关

做什么
位置、用机、电量三个开关，各自独立。关掉某一项，对方读到的该项就是空的，界面写明「她关了位置共享」。
边界
开关只由数据主人控制，对方改不了。关共享不等于暂停，暂停覆盖全部三类。

B1 今日屏幕时间

口径
当天零点到现在，屏幕亮着的累计时长。用 UsageEvents 的亮屏、灭屏事件累加，当前屏还亮着就补到此刻。
展示
大字号显示，配一句与昨天同期的对比。

B2 应用使用排行

口径
每个应用当天前台累计时长，超过 1 分钟的才计入，按降序取前 15。排除本 App 自己。
展示
列表，图标、名称、时长。默认展示前 5，点「展开」看全部。

B5 首次与末次解锁

口径
当天第一个和最后一个 KEYGUARD_HIDDEN 事件的时间。
展示
「今天 7:12 第一次解锁，23:40 最后一次解锁」。
边界
解锁只说明屏幕被解开，不代表之后停止使用。不写「放下手机」，也不据此推断睡觉。

07页面与流程

首次启动

欢迎页 → 登录或注册 → 生成或输入配对码 → 权限引导（三屏）→ 主页

权限引导分三屏，每屏只讲一件事，讲完给一个明确按钮。三屏分别是使用情况访问、定位、后台保活。用户跳过任何一屏，主页顶部挂一条黄色提示条，点进去可以补。

主页

  • 上半屏地图，一个头像
  • 下方卡片：地点、更新时间、电量、相距距离
  • 再下方：今日屏幕时间、Top 5 应用、首末次解锁
  • 右上角：暂停按钮。右下角：设置

用机详情

  • 屏幕时间大字，配昨日对比
  • 应用排行完整列表
  • 解锁次数和时间分布

设置

  • 共享开关：位置、用机、电量的分项控制
  • 暂停共享
  • 常去点管理（v0.2）
  • 账号与解绑

表字段说明
usersid, email, nickname, avatar, created_at密码由 Supabase Auth 托管

app_usageid, user_id, date, package_name, app_label, foreground_ms, launch_count只存 Top 20，避免爆量
user_statususer_id, lat, lng, place_name, battery, charging, online, paused_until, updated_at反范式，主页只查这一张
settingsuser_id, share_location, share_usage, share_battery
为什么要有 user_status

主页每次刷新都去聚合 location_points，会扫掉几十万行。把最新状态反范式写进一张单行表，读一次就够。写入由 App 上报时顺带更新。

09技术架构

层选型理由
后端Supabase 免费档，区域新加坡Auth、数据库、实时推送、行级权限一次到位，零运维
安卓Kotlin + Jetpack Compose功能会长期增加，声明式 UI 维护成本低
安卓定位高德定位 SDK比系统 API 省电，自带逆地理编码
安卓地图高德地图 SDK国内可用，个人开发者免费额度足够
安卓存储Room做离线补传队列
安卓网络Retrofit + OkHttp + Realtime 客户端
iOSSwiftUI + CLLocationManager + CoreMotion只上报位置、电量、步数
iOS 分发GitHub Actions 云编译，AltStore 侧载没有 Mac，七天一签

Supabase 免费档够不够

够。两个人每天按 2880 个位置点估算，一个月不到 20 万行，远低于 500 MB 的库容量。实时消息按 30 秒一次推算，每月约 35 万条，免费档上限 200 万条。带宽同样在额度内。

国内访问的风险

Supabase 的节点在境外，国内访问延迟不稳定，实时位置可能出现几秒到十几秒的滞后。缓解办法有三条：区域选新加坡而不是美西；客户端做本地缓存，断网不丢数据；数据模型用标准 Postgres，随时能整体导出搬到自己的服务器。

迁移预案

如果实测延迟无法接受，把 Supabase 换成「香港 VPS + Postgres + 自建 WebSocket」，App 侧只改配置里的地址，业务代码不动。这是选 Supabase 时就要留好的余地。
